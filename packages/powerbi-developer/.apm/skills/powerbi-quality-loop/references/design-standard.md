# Visualization Design Standard

Apply these rules as an explicit review contract, not as a request to make the
report "modern."

- Give each page one job: audience, decision, page question, and primary visual.
- Use bars or dots for category comparison, lines for time, variance views for
  deviation, and tables or matrices for precise lookup. Do not choose charts
  for variety alone.
- Give every key number units, period, and a meaningful comparator or target.
- Use visual hierarchy deliberately: highlight the important comparison and
  keep supporting content quiet. Empty space is not a requirement to add a chart.
- Use color consistently and never make color the only carrier of meaning.
- Favor direct labels, concise annotations, and removal of non-informative ink.
- Review long labels, negative values, empty states, large values, and actual
  laptop-scale text. Do not approve a page based only on a magnified screenshot.
- Ensure dynamic titles and annotations remain true after slicers change.
- Separate exploratory pages, which support many questions, from explanatory
  pages, which emphasize one supported finding.

Use licensed examples as references with a written rationale. Extract reusable
components and dependencies rather than replacing table names across an entire
third-party template.
